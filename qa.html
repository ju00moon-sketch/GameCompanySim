모든 작업 세션과 완료된 항목은 어디서 보나요?

답변 정리·갱신 2026-11-08

현재 프로젝트에 등록된 세션을 연결 여부와 관계없이 모두 수집합니다. 작업 현황에는 진행·대기·확인 필요 세션을, 완료 탭에는 보고를 마친 세션과 완료 작업을 나눠 표시하며 합계도 함께 보여줍니다.

세션이 마지막 턴을 끝냈더라도 열린 작업이 배정돼 있거나, 터미널 연결·작업 담당 기록을 확인할 수 없거나, 작업 상태가 처음 보는 값이면 현재 목록에 남깁니다. 연결이 끊긴 세션은 ‘연결 끊김’으로 따로 표시합니다. 조용하거나 연결이 없다는 이유만으로 성공 완료 처리하지 않습니다.

실패·반환·취소 작업은 완료 탭의 별도 기록으로 구분합니다. 이후 수정이 성공해도 이전 실패 기록을 성공으로 덮지 않습니다. 협업 도구의 원장에 담당자가 남지 않은 이전 완료 작업은 ‘원장에 담당 기록 없음’으로 그대로 적습니다. 세션의 보고 완료와 게임 기능 완성은 다른 상태입니다.

키보드·마우스, 새 이미지를 넣어서 Meshy AI로 뽑아봤나요?

답변 정리·갱신 2026-11-08

네. 이번 네 개는 총괄이 직접 새 개별 이미지를 넣어 Meshy 생성·다운로드했습니다. G1·G2 키보드와 마우스이며 T2.5 + N1, GLB·FBX를 보관했습니다. 실제 비용은15크레딧씩 총60입니다. 대표의 역할 정정에 따라 이후 보완·검수는 기존 아트 담당에게 인계했습니다.

생성 완료와 외관 합격은 다릅니다. G1 키보드는 일부 키/틈이 무너졌고, G2는 키 블록은 보이지만 키캡·스페이스바가 뒤틀렸습니다. 마우스는 주요 형태를 따라왔지만 휠·버튼 경계·플러그 등 세부가 사진과 다릅니다. 네 개 모두 기존 제품 교체는 보류했습니다.

실제 GLB를 Blender에서 불러와 텍스처와 단색 메시, 위/낮은/사선 각도로 확인했습니다. 목표/실제 삼각형 수와 경계 모서리 검사를 분리해 기록했고 메시 자체는 변형하지 않았습니다. 기존 게임용 폴리곤 상한도 바꾸지 않았습니다. 이때 쓴 임시 생성·렌더 스크립트는 삭제했습니다.

아트 담당이 기존 생성 원본을 활용해 키캡 배열과 마우스 세부를 무료 로컬 작업으로 보완하고 있습니다(ArtSource/Props/KeyboardMouse_ArtReview_20261108). 추가 유료 재생성·제품 모델 덮어쓰기는 하지 않습니다. 아트의 완료 증거를 받기 전에는 통과로 표시하지 않습니다. 아트 렌더 탭의 비교판은 보완 완료본이 아니라 검수 미달 원본이며, 잘리지 않게 원래 비율로 보입니다.

M1·M4에서 무엇이 첫 시험 기준으로 채택됐나요?

답변 정리·갱신 2026-11-08

초기 일반172명,28일마다 새 일반9명, 외부6곳(대1·중견2·소3)이 채택됐습니다. 외부 회사는 공고·평가/선발·입사 제안·고용·인건비 여력만 표현하고 제작·매출·사무실 운영 AI는 제외합니다.

회사당 동시공고1개·28일 새 고용 최대1명은 첫 비교의 상한입니다. 공석·채용 계획·예산이 없으면 뽑지 않습니다. 기업군별 최종 채용 규모를 같게 정한 것은 아닙니다.

같은 사람은 취업/이직/재지원에도 같은 ID와 이력을 유지하고 세계에서 삭제하지 않습니다. 초기/후기 생성 시점을 기록하며, 같은 사람의 반복 등장은 신규 인물로 세지 않습니다.

최종 밸런스는 실제 지원·선발·입사를 확인한 뒤 조정하며, 신규 시장의 생성·지원·선발·경쟁·합류 플레이는 아직 실행하지 않았습니다. 정확한 신입·경력 비율(6:3, 현재 첫 질문), 회사별 초기 고용 장부·정원·인건비 한도·재개·외부 공고 직군·공개 프로필(결정 칸에서 하나씩), 전설의 명단/개인 조건/초반 지원·수락, 특성 분포·최종 확률, 시장 프리미엄, 기존 저장 호환은 승인되지 않았습니다.

회사별 ‘추적 고용0’은 회사 전체 직원이0명이라는 뜻이 아닙니다. 구조 설계안의8자리·한도3,590·급여3,570·잔여20(만원)도 모두 미승인 산술입니다.

신규 유입의 신입·경력 비율은 어떻게 시험하는 게 좋나요?

답변 정리·갱신 2026-11-08

총괄 추천은9명 중 신입6명·경력3명입니다. 신입 우세를 분명히 하면서 경력직 선택지도 남기는 단순한 시험 구성입니다. 정확한 비율은 아직 미승인이며 신입이 더 많다는 방향만 채택됐습니다. 대표 결정 칸의 현재 첫 질문으로 따로 답을 기다립니다.

대안5:4는 경력 선택지가 더 많고,7:2는 신입 중심성이 더 강합니다. 기존 인물의 이직/재지원과 초기 집단은 이 비율에 포함하지 않습니다.

신입·경력은 이력서상의 경력 구분입니다. 신입 비중을 높였다는 이유로 실제 능력·특성 분포를 낮추거나 바꾸지 않습니다. 경력과 실제 능력의 생성 관계는 M3의 별도 검토입니다.

전설급 직원도 초반 스타트업의 일반 채용공고에 자발적으로 지원할 수 있나요?

답변 정리·갱신 2026-11-08

현재 지원 함수에는 회사 규모나 진행 단계만으로 전부 차단하는 규칙은 없습니다. 하지만 고정 전설 생성 경로는 미구현이고 전설별 성향·희망 조건도 미정이므로, 실제 전설이 지금 초반 공고에 지원한다고 확정할 수는 없습니다.

현재 규칙에서는 필수 근무 방식, 조회 가능한 직군, 개인별 지원 의향 임계, 공고/고용 상태가 지원을 막을 수 있습니다. 지원 의향과 최종 제안 수락은 별도입니다.

초기 대표1명·출시0·28일 급여500만원 조건에서 가상 프로필의 지원/수락 계산이 통과하는 것을 실제 코어 함수로 확인했습니다. 전설을 생성해 자연 지원·실제 입사시킨 시험은 아닙니다.

추천은 개인 조건이 맞으면 초반에도 검토하되 보장 출현은 없는 방향입니다. 이번 M1·M4 채택으로 전설의 허용/금지나 일반 인물의 사기 특성 확률까지 정한 것은 아닙니다.

개발 탭 A·B·C는 각각 어떤 역할인가요?

답변 정리·갱신 2026-11-08

A는 제작 코어를 맡습니다. 프로젝트의 작업·공수·검수·진행과 실제 수행 이력 같은 게임 제작 로직이 중심입니다.

B는 사업·저장 코어와 화면 구현을 맡아 왔습니다. 최근에는 대시보드·채용 화면 등 Presentation과 문구 결함을 수정했습니다.

C는 채용 로직을 맡습니다. 지원·제안·판단·수락·통보·고용 상태의 전이가 중심입니다. 통합 담당은 공용 계약·저장·전체 연결을 검토하고 승인된 커밋을 직렬로 처리합니다.

현실 자료를 조사한 뒤 설계를 보완하는 지침은 모델을 바꿔도 유지되나요?

답변 정리·갱신 2026-11-08

공통 지침과 프로젝트 WORK_STATUS에 저장했습니다. Fable5.1 등 모델 변경이나 세션 인계 때도 게임 내 기능·시스템·콘텐츠의 근거 조사 원칙을 이어받도록 명시했습니다.

기존 설계·코드·실측과 현실 게임업계의1차 자료/공식 기술 문서를 먼저 확인하고, 사실·설계 판단·의도적 단순화·시험값·미정을 분리합니다. 근거가 부족하거나 문제가 있는 의견에는 이유와 대안을 제시합니다.

이미 정한 방향은 유지하며 자료로 해결할 수 있는 것을 먼저 해결합니다. 플레이·범위·호환성에 영향을 주는 선택만 추천·대안·영향과 함께 요청합니다. 파일 저장만으로 실행 중인 모든 작업자의 지침이 즉시 갱신됐다고 주장하지는 않습니다.

삼성 브라우저에서 뜬 ‘6283 다운로드 완료 안 됨’은 작업현황 페이지 문제였나요?

답변 정리·갱신 2026-11-08

보내주신 화면은 삼성인터넷의 다운로드 실패 알림입니다.6283을 서버의 HTTP 오류 코드로 확인한 것은 아닙니다.

대표가 T1~T5 대조 페이지에서도 같은 다운로드 알림이 뜬다고 확인했고, 작업현황 페이지만의 문제는 아니라는 데까지 정리됐습니다.

브라우저 내부에서 왜 그 다운로드를 시도했는지 정확한 원인은 확정하지 못했습니다. 근거 없이 현황판 코드의 특정 기능을 원인으로 단정하지 않습니다.
