# GameCompanySim 작업 현황판

https://ju00moon-sketch.github.io/GameCompanySim/

`index.html`은 자동 생성된다(승격된 입력이나 현황이 바뀌면 다시 게시). 기계용 요약은 `status.json`, 비공개 구역을 빼고 내부 경로·식별자를 가린 총괄 기록 공개본은 `status.md`다. 내부 원문 전체를 내려받는 파일이 아니다.

페이지는 같은 탐색 탭 네 개로 나뉜다.
- `index.html`: 작업 현황. 엔진 전환 진행(기준 시각·아직 안 된 것·단계·영역별 진행·원칙·보류한 작업·실측 규모), 담당별 작업 현황(등록 세션 전체의 열린 Task·확인된 진행 기록·미완료 이정표), 현재 세션(등록 세션 전체), 대표 결정, 대기 항목, 오늘 결과. 대표님께 드리는 미답변 질문은 대표 결정 칸 한곳에만 둔다.
- `gallery.html`: Unity 게임 화면 캡처(16:9). 실제 데이터와 미리보기 데이터 표시는 각 그림에 유지한다.
- `art.html`: 검증용 아트 렌더. 맨 위 그룹은 G1 키보드 A/B 제작 방식 비교이며, 아트가 넘긴 `web_handoff.json`에 적힌 개별 렌더(사선·상면·모서리·측면)만 같은 뷰끼리 두 장씩 나란히 놓고 납품값으로 만든 숫자 표 하나를 붙인다. 대표 원시안이 들어간 그림(`reference_full.png`, `comparison_*.png`, 예전 키보드·마우스 Meshy 비교판)과 모델 파일은 게시하지 않고 검수 사실만 글로 남긴다. 렌더는 잘리지 않게 원래 비율로 보인다.
- `closed.html`: 완료. 완료 작업(Task), 목표 기록의 완료 이정표(완료한 빌드 표시, 현재는 Unity판 기록), 이후 결정으로 대체된 이정표, 성공과 따로 세는 실패·반환·취소 기록, 답변으로 종결된 결정과 종결된 대기 항목. 세션은 이 탭으로 옮기지 않는다.

탭은 실제 링크이며 키보드 Enter, 뒤로 가기, 직접 주소 열기를 지원한다. 열린 항목이 없으면 「모두 읽음」 단추와 안 읽음 배지를 그리지 않는다. 읽음 표시는 이 브라우저에만 저장되는 표시이며 답변이나 승인이 아니다. 저장된 읽음 기록(`gcs-read-v1`)이 v1 읽음 맵(항목별 읽은 시각 또는 true)이 아니거나 깨져 있으면 오류 없이 안 읽음으로 시작하고, 읽음 기록은 사용자가 누를 때만 다시 저장한다.

담당별 작업 현황
- 등록 세션마다 카드 하나를 두고, 그 세션에 배정된 열린 Task와 담당이 적힌 미완료 이정표를 보여 준다. 배정이 없으면 '현재 배정 작업 없음 · 다음 배정 대기'로 남긴다.
- 이정표 담당은 목표 기록의 `who`와 그 근거 `who_src`로만 정한다. 담당이 적혀 있지 않거나 담당 세션이 없는 이정표, 진행 중인데 담당 세션을 확인할 수 없는 열린 Task는 '담당 확인 필요'에 모으고 임의로 배정하거나 완료 처리하지 않는다. 아직 배정 전인 Task(`ready` 시작 대기, `pending` 선행 작업 대기)는 '배정 전 Task'에 따로 보이며 담당 누락 경고로 세지 않는다.
- 완료 이정표는 완료 탭에서 원래 제목과 근거를 유지한다. 나중에 커밋·완료 보고와 대조해 완료로 옮긴 단계는 `done_src`에 완료 근거를 남긴다. 작업(Task) 실행 기록과 이정표는 출처와 단위가 달라 건수를 합치지 않는다.
- 이후 결정으로 전제가 바뀐 단계(`state: superseded`)는 작업 현황에서 빼고 완료 탭의 '대체된 이정표'에 대체 관계 메모와 함께 남긴다. 완료 건수에는 넣지 않는다.
- 담당과 근거가 있는 현재 상태(`work_notes`)는 해당 담당 카드에 '진행 기록'으로 붙인다. 아직 없는 결과물의 링크나 이미지 자리는 만들지 않는다.
- 일부러 멈춘 작업은 생성기 입력 `status_content.json`의 `transition.holds`에 Task·공개 제목·담당을 적어 '보류'로 표시한다. 원장 상태가 `blocked`인 동안만 적용하고, 배정이 해제돼도 적어 둔 담당 카드에 붙이며 담당 누락 경고로 세지 않는다. 실패·대표 답변 대기·결함 차단과 구분하며, 적어 두지 않은 `blocked` Task는 기존처럼 '차단'이다. 같은 목록을 작업 현황 맨 위 엔진 전환 진행에도 모은다.
- 목표 기록의 `state: hold` 단계는 '보류' 칩과 함께 멈춘 이유(`hold`)를 먼저 보이고 이전 기록(`s`·`note`)은 그대로 둔다. 미완료 이정표 수에 넣되 보류 수를 따로 적는다.

세션 수집 경계
- 이 프로젝트의 작업 공간과 실행(run)만 읽는다. 다른 프로젝트의 세션은 수집하지 않는다.
- 작업 목록은 전체 기록에서 담당·제목·상태와 보류 대조용 식별자만 남기고 지시 원문과 결과는 버린다. 대조용 Task 식별자와 터미널 식별자는 생성기가 공개 파일에 쓰지 않는다.
- 세션은 상태와 관계없이 모두 현재 세션에 표시한다. 마지막 보고를 마친 세션은 터미널 연결, 모든 열린 작업의 담당, 자기 열린 작업 0이 확인될 때만 '보고 완료·대기'로 표시하고, 확인할 수 없으면 연결 끊김·확인 필요·상태 확인 필요로 구분한다. 조회에 실패하면 현황판에 보류 이유를 적는다(`status.json`의 `checks`).
- 등록 세션은 맨 위 세션과 그 세션이 띄운 담당 세션이다. 담당 세션이 다시 띄운 하위 작업자와 그 하위 배정은 세션 카드·세션 수·열린 Task·담당 누락 집계에 넣지 않고 상위 Task의 일로 본다.
- `status.json`의 열린 Task에는 세션 식별자 `session_id`(터미널 식별자가 아닌 해시)를 붙이고, 담당 세션을 찾지 못하면 비워 둔다.
- 원장에 담당자가 남지 않은 이전 작업은 '원장에 담당 기록 없음'으로, 아직 배정 전인 작업은 '아직 배정 전'으로 적는다. 실행 전에 편성을 바로잡아 취소한 작업(원장 status `failed`, result `cancelled`)은 실패가 아니라 '취소'로 적는다.

공개 투영 경계
- 내부 현황의 지정 비공개 구역은 제목·코드 블록·링크와 경계 주석까지 통째로 제외한다. HTML에서만 숨기지 않으며, 공개 문단·표의 순서와 기존 도구명 제거는 유지한다. 내부 원문과 첨부 장부는 수정하거나 공개 폴더로 복사하지 않는다.
- 시작·종료 주석은 각각 독립 줄이어야 하고 앞뒤 공백은 허용한다. 여러 구역은 허용하지만 중첩은 금지한다. 정확한 형식은 생성기 `publish_status.py`의 운영 설명에 있다.
- 종료만 있는 구역, 닫히지 않은 구역, 중첩, 잘못된 경계 형식은 파일·이미지 쓰기와 게시 전에 명시 오류로 중단한다. 오류를 이유로 원문 전체를 지우거나 나머지를 임의로 공개하지 않는다.
- 실행 환경의 세부는 비공개 구역에만 적는다. 생성기의 지정 낱말(`ENVIRONMENT_TERMS`)이 공개 줄에 있으면 그 줄 번호와 함께, 렌더한 페이지·데이터 파일(내용 파일, 원장 Task 제목, 캡션, 이 README 포함)에 있으면 파일 이름과 함께 명시 오류로 중단하고 페이지를 쓰지 않는다. 낱말을 지우거나 바꿔 쓰지 않으며, 커밋·파일 해시 안의 숫자는 낱말로 세지 않는다.
- 공개 투영은 원문을 한 번 읽는 공통 추출 단계에서 만들고 HTML 렌더·공개 Markdown·변경 감지에 재사용한다. 다른 페이지와 기계용 요약에는 내부 원문을 별도로 넣지 않는다.
- 공개 화면에서 내린 원시안 비교판 4개의 정확한 경로는 생성물에 쓰지 않고 '원시안 비교판 FI11·G1'처럼 바꿔 쓴다. 예전 사본이 Git 기록에 남아 있기 때문이다.
- 총괄 기록 공개본(접힌 공개본과 `status.md`)과 원장의 Task 제목은 공개할 때만 내부 참조를 가린다. 파일 경로는 폴더와 확장자를 뺀 문서 이름으로, 폴더 경로는 '전환 기록 폴더' 같은 중립 이름으로 바꾸고, 작업·메시지·배정 식별자와 커밋·파일 해시는 숨기며, 내부 링크는 글자만 남긴다. 게시 확인용인 이 저장소의 커밋 식별값과 공개 페이지 이름은 남긴다. 내부 원문은 바꾸지 않는다.
- 생성기 입력(`status_content.json`)의 공개 문구에는 내부 파일 경로와 작업 식별자를 쓰지 않는다.
- 관련 회귀 검사는 생성기 폴더에서 `python -B -m unittest -v test_publish_status`로 실행한다.

게시 입력 승격
- 게시기는 편집 중인 파일을 읽지 않는다. 생성기·내용·README·회귀 검사는 작업 사본에서 고치고, `--stage`가 이를 스냅샷 폴더로 복사해 그 안에서 회귀 검사를 돌린 뒤 manifest에 각 파일과 갤러리 입력(승인 캡처·A/B 납품·아트 렌더)의 SHA-256을 적는다.
- 스냅샷의 `--preview`로 공개 사본에 렌더해 확인하고, 확인 근거와 함께 `--promote`하면 승격 표지(스냅샷 이름과 manifest SHA-256) 하나가 한 번에 바뀐다.
- watch(`status_watch.py`)는 매 주기 승격 표지·manifest·스냅샷 파일·고정 입력을 대조하고, 하나라도 다르면 그 주기는 게시하지 않고 이유를 남긴다. 맞으면 그 스냅샷의 게시기만 실행한다. 작업 사본으로 되돌아가는 경로는 없다.
- 승인 캡처 폴더는 스냅샷의 게시기에 고정되고 해시는 manifest에 있다. 새 승인 세트는 새 스냅샷으로만 바뀌며 환경 변수로 바꾸지 않는다. 고정 입력 폴더에 나중에 생긴 파일은 다음 승격 전까지 게시하지 않는다.
- 이 README도 스냅샷에서 저장소로 복사된다. 총괄 기록과 세션·Task 원장은 실시간 입력이며, 비공개 구역 검사와 내부 참조 가리기를 거친다.

결정 자료는 질문·추천 이유·대안·플레이 차이·구현 영향·결정 시점·숫자 상태의 7항목으로 표시한다. 근거 표가 필요한 결정은 `table`(열 이름·행·합계·주석)을 붙이며, 1000px 이상에서는 표로, 그보다 좁은 화면에서는 행마다 열 이름이 붙은 카드로 보인다. 선택은 한 번에 하나씩 묻는 개별 항목으로 올리고, 대표가 실제로 답한 항목만 종결해 답변(`answer`)과 함께 `closed.html`로 옮긴다. 구체안이 없는 후속 세부는 결정 카드로 미리 올리지 않는다.

한 번에 함께 올린 질문은 같은 `group` 값을 주고, 열린 결정 목록에서 그 묶음 앞에 묶음 제목을 한 줄 둔다. 묶음이 다른 질문도 각각 따로 답하는 개별 항목이며 읽음 표시와 종결은 질문마다 따로 처리한다.

답을 받은 결정의 칩은 '답변 완료'로 쓰고, 설계·구현·검증 단계는 `progress`(예: '반영 설계 진행 중')로 따로 적는다. 종결 카드는 대표 답변 요약 아래에 최초 추천안(`initial`), 추천안 대비(`change`), 채택한 방향(`adopted`), 이번에 정하지 않은 것(`open`)을 차례로 보이고, 원래 제목과 검토 7항목은 그대로 둔다. 추천안과 다른 선택(`changed: true`)에는 제목 줄에 '추천안에서 변경' 글자 표시를 단다(색만으로 구분하지 않는다).

종결된 결정을 지금도 답을 기다리는 것처럼 쓰는 문장은 회귀 검사(`ClosedDecisionWordingTests`)가 스냅샷을 만들 때 막는다. 검사 대상은 지금 상태를 말하는 문장(목표 줄, 전환 진행, 대기 항목의 설명과 막힌 작업·필요한 결정·다음 결과물, 종결 카드의 답변·진행·결정 기록, 진행 기록)이며, 검토 7항목과 오늘 결과, 날짜가 붙은 이정표 기록은 과거 기록이라 보지 않는다.
