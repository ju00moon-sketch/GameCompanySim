# GameCompanySim 작업 현황판

https://ju00moon-sketch.github.io/GameCompanySim/

`index.html`은 자동 생성된다(현황 파일이 바뀌면 다시 게시). 기계용 요약은 `status.json`, 비공개 구역을 제외한 총괄 기록 공개본은 `status.md`다. 내부 원문 전체를 내려받는 파일이 아니다.

페이지는 같은 탐색 탭 네 개로 나뉜다.
- `index.html`: 작업 현황. 담당별 작업 현황(등록 세션 전체의 열린 Task·확인된 진행 기록·미완료 이정표), 현재 세션(등록 세션 전체), 대표 결정, 대기 항목, 오늘 결과. 대표님께 드리는 미답변 질문은 대표 결정 칸 한곳에만 둔다.
- `gallery.html`: Unity 게임 화면 캡처(16:9). 실제 데이터와 미리보기 데이터 표시는 각 그림에 유지한다.
- `art.html`: 검증용 아트 렌더. 맨 위 그룹은 G1 키보드 A/B 제작 방식 비교이며, 아트가 넘긴 `web_handoff.json`에 적힌 개별 렌더(사선·상면·모서리·측면)만 같은 뷰끼리 두 장씩 나란히 놓고 납품값으로 만든 숫자 표 하나를 붙인다. 대표 원시안이 들어간 그림(`reference_full.png`, `comparison_*.png`, 예전 키보드·마우스 Meshy 비교판)과 모델 파일은 게시하지 않고 검수 사실만 글로 남긴다. 렌더는 잘리지 않게 원래 비율로 보인다.
- `closed.html`: 완료. 완료 작업(Task), 목표 기록의 완료 이정표, 이후 결정으로 대체된 이정표, 성공과 따로 세는 실패·반환·취소 기록, 답변으로 종결된 결정과 종결된 대기 항목. 세션은 이 탭으로 옮기지 않는다.

탭은 실제 링크이며 키보드 Enter, 뒤로 가기, 직접 주소 열기를 지원한다. 열린 항목이 없으면 「모두 읽음」 단추와 안 읽음 배지를 그리지 않는다. 읽음 표시는 이 브라우저에만 저장되는 표시이며 답변이나 승인이 아니다. 저장된 읽음 기록(`gcs-read-v1`)이 v1 읽음 맵(항목별 읽은 시각 또는 true)이 아니거나 깨져 있으면 오류 없이 안 읽음으로 시작하고, 읽음 기록은 사용자가 누를 때만 다시 저장한다.

담당별 작업 현황
- 등록 세션마다 카드 하나를 두고, 그 세션에 배정된 열린 Task와 담당이 적힌 미완료 이정표를 보여 준다. 배정이 없으면 '현재 배정 작업 없음 · 다음 배정 대기'로 남긴다.
- 이정표 담당은 목표 기록의 `who`와 그 근거 `who_src`로만 정한다. 담당이 적혀 있지 않거나 담당 세션이 없는 이정표, 진행 중인데 담당 세션을 확인할 수 없는 열린 Task는 '담당 확인 필요'에 모으고 임의로 배정하거나 완료 처리하지 않는다. 아직 배정 전인 Task(`ready` 시작 대기, `pending` 선행 작업 대기)는 '배정 전 Task'에 따로 보이며 담당 누락 경고로 세지 않는다.
- 완료 이정표는 완료 탭에서 원래 제목과 근거를 유지한다. 나중에 커밋·완료 보고와 대조해 완료로 옮긴 단계는 `done_src`에 완료 근거를 남긴다. 작업(Task) 실행 기록과 이정표는 출처와 단위가 달라 건수를 합치지 않는다.
- 이후 결정으로 전제가 바뀐 단계(`state: superseded`)는 작업 현황에서 빼고 완료 탭의 '대체된 이정표'에 대체 관계 메모와 함께 남긴다. 완료 건수에는 넣지 않는다.
- 담당과 근거가 있는 현재 상태(`work_notes`)는 해당 담당 카드에 '진행 기록'으로 붙인다. 아직 없는 결과물의 링크나 이미지 자리는 만들지 않는다.

세션 수집 경계
- 이 프로젝트의 작업 공간과 실행(run)만 읽는다. 다른 프로젝트의 세션은 수집하지 않는다.
- 작업 목록은 전체 기록에서 담당·제목·상태만 남기고 지시 원문과 결과는 버린다. 터미널 식별자도 공개 파일에 쓰지 않는다.
- 세션은 상태와 관계없이 모두 현재 세션에 표시한다. 마지막 보고를 마친 세션은 터미널 연결, 모든 열린 작업의 담당, 자기 열린 작업 0이 확인될 때만 '보고 완료·대기'로 표시하고, 확인할 수 없으면 연결 끊김·확인 필요·상태 확인 필요로 구분한다. 조회에 실패하면 현황판에 보류 이유를 적는다(`status.json`의 `checks`).
- `status.json`의 열린 Task에는 세션 식별자 `session_id`(터미널 식별자가 아닌 해시)를 붙이고, 담당 세션을 찾지 못하면 비워 둔다.
- 원장에 담당자가 남지 않은 이전 작업은 '원장에 담당 기록 없음'으로, 아직 배정 전인 작업은 '아직 배정 전'으로 적는다. 실행 전에 편성을 바로잡아 취소한 작업(원장 status `failed`, result `cancelled`)은 실패가 아니라 '취소'로 적는다.

공개 투영 경계
- 내부 현황의 지정 비공개 구역은 제목·코드 블록·링크와 경계 주석까지 통째로 제외한다. HTML에서만 숨기지 않으며, 공개 문단·표의 순서와 기존 도구명 제거는 유지한다. 내부 원문과 첨부 장부는 수정하거나 공개 폴더로 복사하지 않는다.
- 시작·종료 주석은 각각 독립 줄이어야 하고 앞뒤 공백은 허용한다. 여러 구역은 허용하지만 중첩은 금지한다. 정확한 형식은 생성기 `publish_status.py`의 운영 설명에 있다.
- 종료만 있는 구역, 닫히지 않은 구역, 중첩, 잘못된 경계 형식은 파일·이미지 쓰기와 게시 전에 명시 오류로 중단한다. 오류를 이유로 원문 전체를 지우거나 나머지를 임의로 공개하지 않는다.
- 공개 투영은 원문을 한 번 읽는 공통 추출 단계에서 만들고 HTML 렌더·공개 Markdown·변경 감지에 재사용한다. 다른 페이지와 기계용 요약에는 내부 원문을 별도로 넣지 않는다.
- 관련 회귀 검사는 생성기 폴더에서 `python -B -m unittest -v test_publish_status`로 실행한다. 실제 dry-run에도 승인된 고정 캡처 폴더를 `STATUS_CAPTURES_DIR`로 지정하며 전체 캡처 폴더를 자동 재수집하지 않는다.

결정 자료는 질문·추천 이유·대안·플레이 차이·구현 영향·결정 시점·숫자 상태의 7항목으로 표시한다. 근거 표가 필요한 결정은 `table`(열 이름·행·합계·주석)을 붙이며, 1000px 이상에서는 표로, 그보다 좁은 화면에서는 행마다 열 이름이 붙은 카드로 보인다. 선택은 한 번에 하나씩 묻는 개별 항목으로 올리고, 대표가 실제로 답한 항목만 종결해 답변(`answer`)과 함께 `closed.html`로 옮긴다. 구체안이 없는 후속 세부는 결정 카드로 미리 올리지 않는다.
